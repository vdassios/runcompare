# 37 · M3 end-to-end

**Milestone** M3 · **Depends on** 23, 30–36 · **Branch** `task/37-m3-e2e`

## Goal
Prove that insights, climbs, lap-snapping and persistence work together through the real UI, and tune anything that is clearly wrong on the owner's real races.

## You own
`tests/e2e/m3.spec.ts`, the README "Insights" section, and small integration fixes anywhere, each listed with the reason (same rule as task 15).

## Requirements
1. Upload both FIT files. The climbs table appears, and the splits table offers the climbs mode.
2. The insights panel lists at least one insight for 2025 against 2024. Clicking it sets `highlightRanges` and `zoomRange`, and the charts and map show the highlight. Check the store and the presence of a `markArea` in the chart option, through `echarts.getInstanceByDom`.
3. The insight text switches units when the units toggle changes.
4. Add the pro set from task 23. A `vs-split-set` insight appears.
5. Reload. The session, including the pro set, is restored and the insights are the same.
6. **Owner review artifact:** write the complete list of insights produced for `fit-two-attempts` and `fit-vs-pro` (title and filled text, metric) into the PR description, so the owner can judge whether the rule thresholds feel right on their own races. Don't tune the thresholds without the owner's approval.

## Acceptance
- `npm run test:e2e` passes locally (in Docker) and in CI, and all M1 and M2 e2e tests still pass.
- The insights list is in the PR.

Deployment (38).
