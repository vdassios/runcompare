# 37 · M3 end-to-end

**Milestone** M3 · **Depends on** 23, 30–36 · **Branch** `task/37-m3-e2e`

## Goal
Prove that insights, climbs, lap-snapping and persistence work together through the real UI, and tune anything that is clearly wrong on the owner's real races.

## You own
`src/integration/m3.test.tsx`, the README "Insights" section, and small integration fixes anywhere, each listed with the reason (same rule as task 15).

## Requirements
A Vitest integration test on the real pipeline, set up the same way as task 15's `m1.test.tsx`, with `fake-indexeddb` for persistence:
1. Upload both FIT files. The climbs table appears, and the splits table offers the climbs mode.
2. The insights panel lists at least one insight for 2025 against 2024. Clicking it sets `highlightRanges` and `zoomRange`, and the chart options from task 12's builders contain the matching `markArea`.
3. The insight text switches units when the units toggle changes.
4. Add the pro set from task 23. A `vs-split-set` insight appears.
5. Remount the app on a fresh store and hydrate. The session, including the pro set, is restored and the insights are the same.
6. **Owner review artifact:** write the complete list of insights produced for both FIT files, and for both plus the `fit-vs-pro` pro set from task 21 (title and filled text, metric), into the PR description, so the owner can judge whether the rule thresholds feel right on their own races. Don't tune the thresholds without the owner's approval.

## Acceptance
- `npm test` passes locally and in CI, including the M1 and M2 integration tests.
- The insights list is in the PR.
- A manual check in the real app that clicking an insight highlights the stretch on the charts and the map, as in task 15.

Deployment (38).
