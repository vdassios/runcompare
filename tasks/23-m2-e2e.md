# 23 · M2 end-to-end

**Milestone** M2 · **Depends on** 15, 21, 22 · **Branch** `task/23-m2-e2e`

## Goal
Prove that split sets and distance baselines work through the real UI, and fix the integration issues that only appear once the pieces meet.

## You own
`tests/e2e/m2.spec.ts`, the README "Split sets" section, and small integration fixes anywhere, each listed in the PR with the reason (same rule as task 15).

## Requirements
Playwright e2e on the normal build:
1. **A pro on the trail course.**
   - Upload both FIT files, then paste `10 55:00, 25 2:30:00, 54 5:30:00` with official distance 54 km and GAP interpolation, and add it.
   - The pro appears in the attempts list, the KPI Time card, the pace and delta charts (dashed, with marker dots) and the splits table (estimated markers).
   - The delta at each marker matches the pasted times against the baseline's times there. Read it from the store.
2. **Splits only.**
   - In a fresh page, use the target tab to make 10K in 40:00, then paste a pro set `5 14:10, 10 28:30`, and set a distance baseline 10K on the target set.
   - The map section is absent and the delta chart shows the pro at `−11:30` at the finish.
3. **Imperial entry.** With imperial units, paste `3.1 mi 20:00` and check the stored marker is about 4,989 m. Then switch back to metric and the editor shows 4.99 km.
4. **Library.** Save a set, reload the page, and load it again.
5. **Invalid baseline.** Removing the distance baseline's split set falls back to the earliest GPS attempt, or to an empty state with a message.

## Acceptance
- `npm run test:e2e` passes locally and in CI, and all M1 e2e tests still pass.
- Integration fixes are listed.

## Out of scope
M3.
